# CReusableProjectTemplate

A batteries-included starting point for a maintainable, reusable C library.
It builds with modern CMake, ships an install/export config so other CMake
projects can `find_package()` it, and comes with warnings, sanitizers,
static analysis, tests, and CI already wired up.

The library itself (`ctemplate`, a small growable string buffer) is a
placeholder that exists to demonstrate the conventions below. Replace its
contents with your own code and keep the same shape.

## Design principles

- **Opaque types.** Public structs are forward-declared in the header and
  defined only in the `.c` file, so internal layout can change without
  breaking binary compatibility.
- **Explicit ownership.** Every allocating function has a matching
  `_destroy`/`_free` counterpart; `NULL` is always a safe no-op, mirroring
  `free()`.
- **Status codes, not magic numbers.** Fallible functions return an `enum`,
  never `-1`/`errno`/silent truncation.
- **const-correctness** everywhere a parameter or return value is read-only.
- **One export macro.** `CTEMPLATE_API`, generated by CMake's
  `GenerateExportHeader`, makes the same header work for static and shared
  builds on every platform without `#ifdef` soup in your own code.
- **Warnings and sanitizers are opt-in flags, not hardcoded.** The template
  builds cleanly with defaults; turn on `-Werror` and ASan/UBSan for local
  development and CI via CMake options (see below).

## Directory layout

```
.
├── CMakeLists.txt          # top-level build: library, options, install rules
├── CMakePresets.json        # ready-made configure/build/test presets
├── cmake/                   # reusable CMake modules (warnings, sanitizers, static analysis)
├── include/ctemplate/       # public headers (the API surface)
├── src/                     # implementation, private to the library
├── tests/                   # CTest-driven unit tests
├── examples/                # small runnable programs using the public API
├── docs/                    # optional Doxygen configuration
├── third_party/             # where to vendor or FetchContent dependencies
├── scripts/format.sh        # run clang-format over the whole tree
└── .github/workflows/ci.yml # multi-OS build+test, sanitizers, static analysis
```

## Quick start

### Renaming the template for your project

The placeholder name is `ctemplate` / `CTEMPLATE`. To rename it:

1. Replace `ctemplate` -> `yourlib` and `CTEMPLATE` -> `YOURLIB` across the
   repository (a case-sensitive find/replace covers the CMake project name,
   target name, namespace alias, header guards, and the export macro base
   name).
2. Rename `include/ctemplate/` to `include/yourlib/`.
3. Replace the contents of `include/yourlib/yourlib.h` and `src/ctemplate.c`
   with your real API and implementation.
4. Update `LICENSE` (copyright holder) and `README.md`/`CHANGELOG.md` for
   your project.

### Building

With CMake presets (CMake >= 3.19):

```sh
cmake --preset default
cmake --build --preset default
ctest --preset default
```

Other presets: `release` (optimized build), `dev` (warnings-as-errors +
sanitizers, for local development), `shared` (builds `ctemplate` as a
shared library).

Without presets, the equivalent manual invocation:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Run the example:

```sh
./build/examples/basic_usage
```

### Build options

| Option | Default | Purpose |
|---|---|---|
| `BUILD_SHARED_LIBS` | `OFF` | Build `ctemplate` as a shared library instead of static. |
| `CTEMPLATE_BUILD_TESTS` | `ON` at top level | Build the CTest suite. |
| `CTEMPLATE_BUILD_EXAMPLES` | `ON` at top level | Build the programs under `examples/`. |
| `CTEMPLATE_BUILD_DOCS` | `OFF` | Add a `docs` target that runs Doxygen (requires Doxygen installed). |
| `CTEMPLATE_WARNINGS_AS_ERRORS` | `OFF` | Promote compiler warnings to errors. |
| `CTEMPLATE_ENABLE_SANITIZERS` | `OFF` | Build with AddressSanitizer + UndefinedBehaviorSanitizer (GCC/Clang). |
| `CTEMPLATE_ENABLE_CLANG_TIDY` | `OFF` | Run `clang-tidy` during the build, if it's installed. |
| `CTEMPLATE_INSTALL` | `ON` at top level | Generate `install()` and CMake package-config rules. |

When this project is added via `add_subdirectory()` from another project,
`CTEMPLATE_BUILD_TESTS`, `CTEMPLATE_BUILD_EXAMPLES`, and `CTEMPLATE_INSTALL`
all default to `OFF` automatically, so consuming it doesn't drag in its
tests or clash with the parent project's own install rules.

### Using ctemplate from another project

**As a subdirectory or `FetchContent`:**

```cmake
add_subdirectory(path/to/CReusableProjectTemplate)
target_link_libraries(your_target PRIVATE ctemplate::ctemplate)
```

**As an installed package**, after `cmake --install build`:

```cmake
find_package(ctemplate REQUIRED)
target_link_libraries(your_target PRIVATE ctemplate::ctemplate)
```

## Testing

Tests live in `tests/` and run under CTest. They use a small,
dependency-free assertion header (`tests/test_framework.h`) so the suite
builds with nothing beyond a C compiler; swap in Unity, Criterion, or
CMocka for a larger project.

```sh
ctest --test-dir build --output-on-failure
```

## Code style and static analysis

- `.clang-format` defines the formatting style; run `scripts/format.sh` to
  apply it to the whole tree.
- `.clang-tidy` defines the lint rule set; enable it during the build with
  `-DCTEMPLATE_ENABLE_CLANG_TIDY=ON`.
- `.editorconfig` and `.gitattributes` keep whitespace and line endings
  consistent across editors and platforms.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request against
`main`:

- a build-and-test matrix across Ubuntu, macOS, and Windows in Debug and
  Release;
- a dedicated job building and testing under AddressSanitizer/UBSan;
- a static-analysis job that checks formatting with `clang-format` and
  builds with `clang-tidy` enabled.

## Versioning and changelog

The project version lives in the top-level `project(... VERSION x.y.z)`
call. `CHANGELOG.md` follows the
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format; add an
entry there with every user-facing change.
